# 排序与数据来源

## 数据

| 用途 | 来源 | 许可 |
| --- | --- | --- |
| 词库 | `download.fcitx-im.org/data/dict-20260907.tar.zst` → `dict_sc.txt` | LGPL-2.1-or-later |
| 词频 | [rime-essay](https://github.com/rime/rime-essay) 的 `essay.txt`，按 commit `054920d` 钉住 | LGPL-3.0 |
| 简繁对照 | OpenCC 的 `STCharacters.txt`，已内置在 `scripts/` | Apache-2.0 |
| 注音（自造词用） | 上面那份词库里的单字条目，构建时抽出 | LGPL-2.1-or-later |

词库带 SHA256 校验，校验值取自 libime 的 `data/CMakeLists.txt`；语料没有公布校验值，
所以用 commit 钉住 URL 而不是校验和。四个资源都由 `scripts/build_dict.py` 在构建期
生成到 `app/src/main/assets/`，不进 git。

## 排序怎么定的

官方词库没有词频：30 万条里只有 1498 条带一个相对字频，其余全是 0。所以词序来自 RIME
八股文的真实语料计数 —— 它是繁体写的，先经 OpenCC 表折回简体再计数（这一步有损：
干 / 乾 / 幹 会并成一个，计数相加）。

1. 有计数的词（21 万条，占 70%）排在前面，按 `log(计数)` 归一化。
2. 没有计数的词退回启发式：字在多少词条里出现、它出现在的词条有多常用、词库自带的负
   字频；整体压在语料带之下，所以任何有语料证据的词都赢过没有的。
3. 用户学习在最上面：选过的词置顶，存在 `user.txt`。

CI 每次构建都会打印排序探针，可以直接看到结果：

```text
DICTDEBUG wo -> [我:62418, 喔:50711, 窝:49078, 握:48010, 卧:47410]
DICTDEBUG de -> [的:65535, 地:57604, 得:56663, 德:51272, 底:50767]
DICTDEBUG ni -> [你:61965, 呢:58872, 拟:49514, 尼:49279, 泥:48871]
```

## 已知短板

- 剩下 30% 没有语料证据的词，内部顺序只是启发式。
- 整句层面（`women` → 我们 / 卧扪）还没有语言模型；官方 `lm_sc.arpa` 是
  LGPL-2.1-or-later，可以后加。
- 单元测试只保证常用字排第一，不保证整条候选列表都符合直觉。
